# 利用者の私物の iPhone で流すテスト

iOS の実機のテストは、利用者の私物の iPhone で流す。試験用の端末ではなく、個人のデータ（クリップボード、通知、写真、ほかのアプリ、設定）が入っている。この決まりは、このリポジトリで作業するすべての agent と、そこから頼まれた agent（サブエージェント、`unity-native-plugin` など別のリポジトリの agent を含む）に当てはまる。

- 端末: iPhone XS、iOS 18.7.2（最小 iOS の基準の環境。`artifact/topics/ios-c-abi/README.md` の D-21）
- ランナー: `scripts/test_ios.sh`（守り方は `artifact/topics/ios-c-abi/designs/2026-10-18-ios-c-abi-ui-test-design.md` の U-9 と 6.3）

## 流す前に、毎回許可を得る

実機でテストを流す前は、どんなテストでも利用者に次の 4 つを知らせ、はっきり許可を得る。許可は 1 回限りで、次の実行や別の操作には広げない。サブエージェントやほかの agent にも、許可を得る前に実機で流させない。

1. 流すテストの一覧と区分（`--dry-run` の出力と許可の ID）
2. 端末に起きること（アプリの入れ直し、通知、ホーム画面や「設定」への移動、共有のシートなど）
3. 利用者に事前にしてもらうこと（下の「準備」）
4. 時間の見込み

`scripts/test_ios.sh` は `--dry-run` で許可の一覧を書き、`--approved` でそれを照らしてから実機に触れる。許可の ID は 1 回使うと使えなくなる。止まった後の流し直しにも、新しい `--dry-run` と許可が要る。

シミュレーターだけのテスト（`scripts/ios_ui_runner.py` の `SIMULATOR_ONLY_TESTS`。Control Center を決まった座標のドラッグで引き出す D22 など）は、`--device-allow` に何を渡しても実機では流れない（一覧に `simulator only` と出る）。実機で流したくなっても、この表から外さない。外すには、座標に頼らない操作に直し、UI テストの設計書（6.3 の 3）を改めてからにする。

## 1 回ごとに聞く操作

次の操作は、何をするかを示して、その都度許可を得る。

- アプリの削除・入れ直し、権限のリセット、端末の設定の変更、再起動、構成プロファイル
- クリップボードを読む・書き換えるテスト（私物の内容を読む・上書きする）
- 共有のシートから実在のアプリ（メッセージ、メール、SNS など）へ送りうる操作（送る操作はしない）
- 通知センターの操作、springboard を操作する UI テスト全般
- 写真・「ファイル」への保存

読むだけの操作（`xcrun devicectl list devices`、端末の情報やアプリの一覧の取得）は聞かなくてよい。アプリの一覧を読むときも、サンプルに関係するものだけを取り出して見る。

## 準備（利用者にしてもらう）

端末の設定は agent から変えない。必要なものは利用者に頼む。

- ロックを解除し、自動ロックを「なし」にする。給電する
- 集中モードを入れ、通知を許すアプリをサンプル（IosLibraryExample）だけにする（私物の通知の割り込みで UI テストが落ちた）
- その集中モードの「ホーム画面 > 通知バッジを非表示」をオフにする（オンだとアイコンのバッジが読めない）
- 流す時間に、予定で始まる別の集中モード（睡眠など）が重ならないようにする（入れ替わるとサンプルの通知が出なくなる）
- クリップボードのテストを流すときは Handoff を切る
- サンプルと同じ表示名の古いアプリ（例: 前の bundle id のサンプル）を消しておく

流す直前に、`xcrun devicectl device info details` などの読むだけの操作で開発用の接続（tunnel と Developer Disk Image）が使えることを確かめる。切れていると、テストのランナーが結果を返さずに止まる。

## 私物を残さない・書かない

- リポジトリは公開している。端末を特定する値（ハードウェアの UDID、devicectl の識別子）は、ファイル・コミット・ログの写しに書かない。伏せ字か環境変数にする
- 実機の `.xcresult` には私物の画面のスクリーンショットが入る。結果を書き写したら消す。添付を書き出さない（`scripts/test_ios.sh` は実機の結果を一時フォルダーごと消す）
- 実機では、画面の階層のダンプを出さず、失敗の文に springboard のラベルを書かない。唯一の例外は、利用者が承認した N5 の手がかり（サンプル名・期待した題・本文を `<app>` / `<title>` / `<body>` に置き換え、ほかは文字数だけ。UI テストの設計書の U-8 (3)）
- シミュレーターはこの決まりの対象外
