# 利用者の私物の iPhone で流すテスト

iOS の実機のテストは、利用者の私物の iPhone で流す。試験用の端末ではなく、個人のデータ（クリップボード、通知、写真、ほかのアプリ、設定）が入っている。この決まりは、このリポジトリで作業するすべての agent と、そこから頼まれた agent（サブエージェント、`unity-native-plugin` など別のリポジトリの agent を含む）に当てはまる。

- 端末: iPhone XS、iOS 18.7.2（最小 iOS の基準の環境。`artifact/topics/ios-c-abi/README.md` の D-21）
- ランナー: `scripts/test_ios.sh`（守り方は `artifact/topics/ios-c-abi/designs/2026-10-18-ios-c-abi-ui-test-design.md` の U-9 と 6.3）

## 流す前に、毎回許可を得る

実機でテストを流す前は、どんなテストでも利用者に次の 4 つを知らせ、はっきり許可を得る。許可は 1 回限りで、次の実行や別の操作には広げない。サブエージェントやほかの agent にも、許可を得る前に実機で流させない。

1. 流すテストの一覧と区分（`--dry-run` の出力と許可の ID）
2. 端末に起きること（アプリの入れ直し、通知、ホーム画面や「設定」への移動、共有のシートなど）
3. 利用者に事前にしてもらうこと（下の「準備」）
4. 時間の見込み

`scripts/test_ios.sh` は `--dry-run` で許可の一覧を書き、`--approved` でそれを照らしてから実機に触れる。許可の ID は 1 回使うと使えなくなる。止まった後の流し直しにも、新しい `--dry-run` と許可が要る。

シミュレーターだけのテスト（`scripts/ios_ui_runner.py` の `SIMULATOR_ONLY_TESTS`。Control Center を決まった座標のドラッグで引き出す D22 など）は、`--device-allow` に何を渡しても実機では流れない（一覧に `simulator only` と出る）。貼り付けのコントロールを押す CB3・CB4（実機の自動の実行で失敗した。合成のタップを受け付けない見込みで、確かめていない）と、実機で貼り付けのアラートが出なかった CB1 もここに入れ、実機では人の確認 HC11・HC12・HC13（`ios/IosLibraryExample/ComputerUse/`）で確かめる。実機で流したくなっても、この表から外さない。外すには、座標に頼らない操作に直し、UI テストの設計書（6.3 の 3）を改めてからにする。

C ABI の UI テスト（`ios/IosLibraryCApiUITests`。`scripts/test_ios.sh --capi-ui`）もシミュレーターだけで、2 つのターゲットは `iphonesimulator` だけを組む。コマンドラインの上書きなら実機向けに組めるが、実機に入れることはこの文書の許可なしには行わない。

C ABI の確かめ（`scripts/test_ios.sh --capi`）もシミュレーターだけで、実機の UDID を拒む。実機での `IosLibraryCApiTests` の ASan と smoke は `--capi-device` で流し、区切りのときだけ、この文書の許可（`--dry-run` の一覧と `--approved`）を得て行う。`--capi-device` が実機に入れる 2 つのアプリ（テストのホストと smoke）は消さずに残る。消すときは、そのたびに聞く。

## 1 回ごとに聞く操作

次の操作は、何をするかを示して、その都度許可を得る。

- アプリの削除・入れ直し、権限のリセット、端末の設定の変更、再起動、構成プロファイル
- クリップボードを読む・書き換えるテスト（私物の内容を読む・上書きする）
- 共有のシートから実在のアプリ（メッセージ、メール、SNS など）へ送りうる操作（送る操作はしない）
- 通知センターの操作、springboard を操作する UI テスト全般
- 写真・「ファイル」への保存

読むだけの操作（`xcrun devicectl list devices`、端末の情報やアプリの一覧の取得）は聞かなくてよい。アプリの一覧を読むときも、サンプルに関係するものだけを取り出して見る。

## 準備（利用者にしてもらう）

端末の設定は agent から変えない。必要なものは利用者に頼む。

- ロックを解除し、自動ロックを「なし」にする。給電する
- 集中モードを入れ、通知を許すアプリをサンプル（IosLibraryExample）だけにする（私物の通知の割り込みで UI テストが落ちた）
- その集中モードの「ホーム画面 > 通知バッジを非表示」をオフにする（オンだとアイコンのバッジが読めない）
- 流す時間に、予定で始まる別の集中モード（睡眠など）が重ならないようにする（入れ替わるとサンプルの通知が出なくなる）
- クリップボードのテストを流すときは Handoff を切る
- サンプルと同じ表示名の古いアプリ（例: 前の bundle id のサンプル）を消しておく

流す直前に、`xcrun devicectl device info details` などの読むだけの操作で開発用の接続（tunnel と Developer Disk Image）が使えることを確かめる。切れていると、テストのランナーが結果を返さずに止まる。

## 私物を残さない・書かない

- リポジトリは公開している。端末を特定する値（ハードウェアの UDID、devicectl の識別子）は、ファイル・コミット・ログの写しに書かない。伏せ字か環境変数にする
- 実機の `.xcresult` には私物の画面のスクリーンショットが入る。結果を書き写したら消す。添付を書き出さない（`scripts/test_ios.sh` は実機の結果を一時フォルダーごと消す）
- 実機では、画面の階層のダンプを出さず、失敗の文に springboard のラベルを書かない。唯一の例外は、利用者が承認した N5 の手がかり（サンプル名・期待した題・本文を `<app>` / `<title>` / `<body>` に置き換え、ほかは文字数だけ。UI テストの設計書の U-8 (3)）
- シミュレーターはこの決まりの対象外。ただし次の節の「Mac のクリップボード」は守る

## Mac のクリップボード（シミュレーター）

この Mac では Simulator.app の「Automatically Sync Pasteboard」がオン（`defaults read com.apple.iphonesimulator PasteboardAutomaticSync` が 1）。Simulator.app が開いていると、シミュレーターの general pasteboard への書き込みが利用者の Mac のクリップボードに届き、Mac 側のコピーがシミュレーターに入ることがある。どちらも測っていない（測ると Mac のクリップボードに触れる）。Simulator.app が閉じていれば届かないことも測っていない。

次を 2026-11-06 に利用者が決めた。

- シミュレーターでテストやアプリを動かす間（UI テスト、`IosLibraryCApiTests` などの単体テスト、手で動かすときを含む）、agent は Simulator.app を開かない。`scripts/test_ios.sh` は `xcodebuild` と `simctl` だけを使い、Simulator.app を開かない
- 流す前に `pgrep -x Simulator` で、Simulator.app が開いていないことを確かめる。開いていたら agent は閉じず、利用者に知らせて閉じてもらうまで流さない
- UI テストの設計書の U-19 の computer use で Simulator.app を開くときは、その都度利用者の許可を得る
- この設定を agent から変えない。Mac のクリップボードを読み書きしない（Mac の `pbcopy`、`pbpaste` と、Mac とシミュレーターを同期する `xcrun simctl pbsync` を使わない）。`xcrun simctl pbcopy`、`pbpaste` はシミュレーターの中だけを読み書きするので使ってよい

# 利用者の私物の Mac で流すテスト（macOS）

macOS にはシミュレーターが無く、macOS のテストは利用者が今使っているこの Mac か、この Mac の上の VM で動く。この Mac には個人のデータ（クリップボード、通知、ファイル、ほかのアプリ、設定）が入っている。この節は 2026-11-22 に利用者が決めた（`artifact/topics/macos-c-abi/plans/2026-11-22-macos-c-abi-decisions.md` の D-21・D-23）。**2026-11-28 に利用者が D-21 を見直した: macOS 26 も tart の VM で確かめ、この Mac では UI テストを流さない**（押す直前に来た利用者の通知がテストのクリックを取りうる間を、許可の仕組みでは縛れないため。Codex の押下の直しのレビュー v1 の A-1）。iOS の節と同じく、このリポジトリで作業するすべての agent と、そこから頼まれた agent に当てはまる。

- この Mac: macOS 26 の最新（2026-11-22 は 26.7.3）、Xcode 26.6（ビルドと dist）と 26.3（`xcode-select` の既定）。UI テストは流さない
- 15 の VM: tart の `ntk-macos-15-new`（15 の最新、Xcode 26.3。`test_mac.sh --where vm`）
- 26 の VM: tart の `ntk-macos-26`（この Mac の Xcode 26.6 を写した。`test_mac.sh --where vm26`。2026-11-28 に作った。26.7.3 へは空きが足りず上げられず、今は 26.6.2（25G83）。26.7 のイメージで作り直す）
- ランナー: `scripts/test_mac.sh`（段階 0d で作る。それまでは、流すたびに下の 4 つを示して許可を得る）
- この Mac では、ランナーは自分の子にしか signal を送らず、前の回の残骸は止めずに知らせる（止めるのは利用者で、再起動でも消える。2026-11-23 のランナーのレビュー v5）

## テストの区分

| 区分 | 例 | この Mac で | 資格のある VM で |
|---|---|---|---|
| 1. 私物に触れない単体テスト | `MacLibraryTests`（名前付きか unique の貼り付け板だけを使い、通知センターと本物の共有のサービスに届かないもの）、`UnityMacPluginTests` の parser、C ABI のテストのうち純粋な検査（NULL、`struct_size`、UTF-8、ハンドル） | 許可なし | 許可なし |
| 2. 私物に触れるテスト | 一般の貼り付け板を読む・書く・消す（`UnityMacClipboardBridgeTests` は消す）、通知を出す・許可を求める、共有のサービスを開く、保存のパネルでファイルを書く、Dock のバッジ、サンプルのアプリを起動する単体テスト（`MacLibraryExampleTests` は通知の delegate を設定する）、C ABI のテストのうちホストが要るもの | 毎回の許可 | 許可なし |
| 3. 画面を使うテスト | UI テスト、C を呼ぶ UI テスト、computer use の人の確認 | **UI テストと C を呼ぶ UI テストは流さない**（2026-11-28 の D-21 の見直し。ランナーは `--where mac` で UI テストを 0 件にし、選ぶ指定を拒む）。computer use の人の確認は毎回の許可と時刻の取り決め | 許可なし（computer use で VM のウインドウを見るときも、この Mac の画面が写るので許可を得る） |

- 区分 1 と宣言する前に、テストの本文と、ホストのアプリの起動の処理を、本物の `NSSharingService`・一般の貼り付け板・通知センターに届きうる経路で洗う。固定の待ちに頼るもの（`SharePickerPresenterTests` は 50 ms の待ちが外れると本物のメールの作成を開きうる）は、直すまで区分 2 にする
- 区分 2・3 は、15 と 26 の資格のある VM で流す。26 にしか無いテストも 26 の VM で流す。UI テストの基準も VM ごとに取る（15 の VM の基準と 26 の VM の基準）。区分 2 をこの Mac で流すのは、VM で流せない理由を示して毎回の許可を得たときだけにする
- テストは一般の貼り付け板でなく、名前付きか unique の貼り付け板を既定にする

## 流す前に、毎回許可を得る（この Mac で区分 2 か computer use の人の確認をするとき）

iOS の実機と同じく、次の 4 つを知らせてはっきり許可を得る。許可は 1 回限りで、次の実行や別の操作には広げない。サブエージェントやほかの agent にも、許可を得る前に流させない。

1. 流すテストの一覧と区分（`test_mac.sh` ができた後は `--dry-run` の出力と許可の ID）
2. この Mac に起きること（アプリが前面に出る、通知が出る、クリップボードが書き換わる、共有のピッカーやパネルが出るなど）
3. 利用者に事前にしてもらうこと（下の「準備」）
4. 時間の見込みと、始める時刻（テストの間、この Mac は使えない）

## 許可なしで流せる VM の条件

VM の中で区分 2・3 を許可なしに流せるのは、次をすべて満たす VM だけである。満たさない VM は、この Mac と同じに扱う。15 の VM と 26 の VM に同じ強さで当て、ランナーは VM ごとの IOPlatformUUID・OS と Xcode の版で、どちらの VM かを取り違えずに確かめる。

- 個人のアカウント（Apple アカウントなど）でサインインしていない
- この Mac とクリップボードを共有しない（`tart run --no-clipboard` で起動する）
- この Mac のフォルダーを共有しない（`tart run` に `--dir` を付けない）。ファイルの受け渡しは `ssh` に `tar` を流す形で行う（`scp -r` は framework の symlink を実体にして署名を壊す）
- 合成のデータだけを使い、実のサービス（メール、メッセージ、AirDrop など）へ送らない

## 1 回ごとに聞く操作（この Mac）

次の操作は、何をするかを示して、その都度許可を得る。

- アプリの削除・入れ直し（LaunchServices に登録された同じ bundle id の余分なコピーを外すことを含む）、権限のリセット（`tccutil reset` など）、通知の許可の変更、システム設定の変更、macOS の更新、再起動
- 一般の貼り付け板を読む・書く・消すテスト（区分 2。テストの中で私物の内容を退避して戻すこともしない。退避は読むことになるため）
- 共有のピッカーから実在のサービスへ送りうる操作（送る操作はしない）
- 通知センターの操作、保存のパネルでファイルを書くこと、Dock のバッジ
- computer use でこの Mac の画面を見ること
- tart の VM の作成・更新（OS と Xcode）・複製・削除、取り込み済みのイメージの削除（`tart prune`）。この Mac のディスクとネットワークを使うため

読むだけの操作（`sw_vers`、`xcodebuild -version`、`tart list`、`tart get`、`codesign -dv`、`nm`、`otool`、`plutil`、`defaults read` で自分のアプリの設定を見ること）は聞かなくてよい。

## 準備（利用者にしてもらう）

この Mac の設定は agent から変えない。必要なものは利用者に頼む。

- 区分 3 を流す間は、マウスとキーボードに触れない（テストが前面を取り、入力が混ざると落ちる）

- 区分 3 で必要になる許可（XCUITest のアクセシビリティなど）は、利用者が与える

- 画面の階層のダンプを出さない。失敗の文に、ほかのアプリや通知の文字を書かない
