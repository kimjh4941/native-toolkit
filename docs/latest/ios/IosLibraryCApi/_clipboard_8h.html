Detailed Description

The clipboard: copying, reading, the description of the contents and change events.

Rules for the whole C ABI (C ABI design part 1, chapter 1): every function may be called from any thread, except ntk_notification_install (main thread only), and none waits for the main thread; completions, events and accepted releases arrive on the main thread; strings are NUL-terminated UTF-8; this header is C99, includes only <stddef.h> and <stdint.h> (through Common.h), and is ASCII only. The declarations are those of Appendix A of the C ABI design part 2, which scripts/check_c_abi_contract_ios.py compares with this file.

The rules of this header (design part 1, chapter 1):

  • Every function can be called from any thread and never waits for the main thread. Completions, events and an accepted call's release run on the main thread, and never inside the function when you call it on the main thread; called elsewhere, a completion can come before the function returns, before an output parameter is visible. Match results through user_data.
  • NONE from a function with a completion callback means accepted, and then the callback comes exactly once while the process lives (dialogs and shares: see their callback types). A listener gets zero or more events until it is removed. Any other value means rejected: no callback, and release (if not NULL) has already been called on your thread. Do not free user_data yourself then. A NULL callback is rejected.
  • After removing a listener off the main thread, events can still come until release. Free user_data in release, not when the function returns.
  • Callbacks must not let exceptions escape, and must not block the main thread for long.
  • Text comes back as UTF-8; invalid surrogates and U+0000 become U+FFFD.
  • Zero-filled means every field except struct_size.
  • Enumerations can grow: write a default branch.

Loads one item of kind. Does not stop the main thread.
