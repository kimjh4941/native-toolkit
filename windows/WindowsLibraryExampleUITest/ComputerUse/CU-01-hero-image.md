# CU-01 画像付き通知の画像

| 項目 | 内容 |
|---|---|
| 対象 | Notification の `ShowWithImage`（ヒーロー画像付きの通知） |
| 確かめること | 通知に表示される画像が、サンプルの `windows/WindowsLibraryExample/Assets/StoreLogo.png` であること |
| FlaUI との分担 | 画像の要素があることは FlaUI の N-06 が確かめる。どの画像かは UI Automation では分からないので、ここで確かめる |
| 実行する人 | Claude のデスクトップアプリの computer use。VS Code のセッションからは実行できない |
| 根拠 | `artifact/topics/windows-architecture/README.md` 7.2、7.3。UI テストの設計書 7 章 |

## 1. 前提

- `scripts/test_windows.ps1` を実行し終えている（サンプルが最新のビルドで配置され、UI テストが終わっている）
- **Clipboard の UI テストが実行中でない。** 画面の撮影がクリップボードに書き込む場合がある
- サンプルアプリが起動していない
- 集中モード（応答不可）はどちらでもよい。確かめるのは通知センターの中で、バナーは使わない
- 画面がロックされていない

## 2. 期待する画像

`StoreLogo.png` は、プロジェクトのテンプレートの既定の画像（50×50）。薄い灰色の正方形の枠の中に、対角線が 2 本（X の形）描かれている。

通知センターでは、この画像が通知の幅いっぱいに拡大され、横長（約 2:1）の枠に収まるように **上半分だけ** が表示される。そのため、見え方は次のとおり。

- 背景は白に近い灰色
- 上の辺と左右の辺に、ぼやけた灰色の太い線がある（正方形の枠の上半分）
- 左上と右上の角から、灰色の斜めの線が 1 本ずつ中央の下へ向かい、画像の下の端の中央付近で交わる（X の上半分。封筒のふたのような形）
- 拡大されているので輪郭はぼやけている

## 3. 操作の手順

1. スタートメニューから **Native Toolkit Example** を起動する。**起動の操作は 1 回だけにする**（2 回行うとウィンドウが 2 つ開く。開いてしまったら、後片付けですべて閉じる）
2. メイン画面で **Notification Example** を押す
3. **InitializeManager** を押す。上部の結果の表示が `✅ [InitializeManager]` で始まることを確かめる
4. **RemoveAll** を押し、前の通知を消す
5. **ShowWithImage** を押す。結果の表示が `✅ [ShowWithImage] errorCode=0` になることを確かめる
6. `Win + N` で通知センターを開く
7. **Native Toolkit Example** のグループの中から、タイトルが **With Image**、本文が **Toast with hero image** の通知を探す
8. 通知が折りたたまれていれば展開し、画像全体が見える状態にする
9. 2 章と見比べ、判定する（4 章）
10. スクリーンショットを撮る（5 章）
11. 後片付け: 通知センターを閉じ、サンプルで **RemoveAll** を押し、サンプルのウィンドウをすべて閉じる。通知センターは `Esc` で閉じる。computer use の権限で通知センターにキーを送れない場合は、サンプルのウィンドウをクリックして閉じる

## 4. 合格の条件

次をすべて満たせば合格。

- 手順 7 の通知の中に画像が表示されている
- 画像が 2 章の見え方と一致する（灰色の枠の上半分と、中央の下で交わる 2 本の斜線）

次のどれかに当たれば失敗。

- 画像の場所が空白、または読み込みに失敗したことを示す表示になっている
- 別の画像（アプリのアイコン、写真、単色など）が表示されている
- 画像が無い
- **判定があいまいな場合も失敗とする**（README 7.3）。その場合は、何があいまいだったかを結果に書く

## 5. 証拠として残すスクリーンショット

- **サンプルアプリの「With Image」の通知 1 件の範囲だけ** に切り取る。通知センター全体や、ほかのアプリの通知は写さない
- 保存先: `windows/WindowsLibraryExampleUITest/ComputerUse/evidence/CU-01/<日付>-<段階>.png`（例: `2026-09-19-0d.png`）。コミットする
- その段階の結果のファイルに、判定（合格／失敗）とスクリーンショットのパスを書く

## 6. 参考: 段階 0c で撮影した見え方

段階 0c に FlaUI で通知の要素だけを撮影して、2 章の見え方を確かめた（2026-09-19、Windows 11 Home 26200）。

- 通知の項目: 334×295
- 画像の要素: 334×180（通知の幅いっぱい、約 1.86:1）

画面の倍率やシェルの更新で大きさは変わりうる。変わっても、2 章の形が見えていれば合格とする。
