\doxysubsection{Detailed Description}
Toast notifications, their content and the values they carry back. 

Part of the public C++ API added in stage 3 of the windows-\/architecture topic (design section 8). This header carries the content types; the Manager and Runtime that use them arrive with OP-\/07..OP-\/20.

The fields come from what the JSON payload of the 1.\+x C ABI accepted, listed in designs/2026-\/09-\/20-\/windows-\/architecture-\/c-\/abi-\/input-\/inventory.\+md section 1. That payload is gone (stage 5), but the "{}\+JSON\+: $<$key$>$"{} notes below stay\+: they are how a field is traced back to the inventory, and to what Notification\+Payload\+Test pins. One shape there does not reduce to fixed fields and is kept open\+: a button\textquotesingle{}s arguments are an arbitrary string map.

Several fields are optional where a plain string would do, because the platform tells an absent value from an empty one and the two are not the same\+: an empty title is a blank line on the toast, an empty image URI is a failure rather than no image, and whether a button carries arguments at all is what decides its exclusivity with invoke\+Uri. Section 1.\+10 of the input inventory lists the ten places this matters, derived from the implementation. The fields that are plain strings were checked the same way and come out identical either way.

Keep this header ASCII only.
