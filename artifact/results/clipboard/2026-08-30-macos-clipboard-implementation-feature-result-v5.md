## 2. 指摘 2 件の反映

### M-7: BT-25 が全 endpoint の回帰を検出しない

**指摘の内容**: 検査が「行を絞ってから式を探す」2 段構えだったため、`clipboardProvideFilePromise`
の引数行のように `(unsigned long)` で始まる行が第 1 段で除外され、そこを平文に戻しても検出できなかった。
`?:` を使わず直接 `%s` に渡す回帰も見逃す。

**対応**: 検査を**行ベースから引数ベース**へ作り直した。

```
endpoint ごとに関数本体を分割
 → stringWithFormat: の引数リストのみ抽出（フォーマット文字列は除外）
 → signature が取る payload 引数それぞれについて
     helper 呼び出しを除去してもなお識別子が残れば漏えい
```

- フォーマット文字列を除外するのが要点。識別子は `"scopeJson: %@"` のようにラベルとしても現れるため、
  除外しないと全 endpoint が偽陽性になる
- `?:` の有無に依存しないため、生ポインタ・`strlen`・任意の書き方を捕まえる
- **監査が空振りしていないことを確かめるテスト**（examined 件数の下限）も追加した。
  前回はこれが無いまま 3 endpoint を見逃していた

**副次的に現物の不整合が 2 件見つかった**。手書きした endpoint が前回の一括置換から外れていた。

| endpoint | 内容 |
|---|---|
| `clipboardProvideFilePromise` | `NTLen` ではなくインライン `strlen`。秘匿はされていたが不統一 |
| `clipboardReceiveFilePromises` | `policyJson` が `%s` で平文。`destinationPath` は未出力 |

指摘は「回帰検査の不足」だったが、検査を正した結果として実装の不整合も解消した。

**監査の実効性を確認した**: 意図的に 1 endpoint を平文へ戻すと 2 テストが落ち、戻すと通る。
