## 方針の変更（親が推奨案で決めた）

Codex A-1〜A-3 は、どれも「この Mac で、外のプロセスの番号を照らしてから signal を送る」形の穴だった（照らせないときの扱い、追い切れない group、照らしと送りの間の使い回し）。照らしを足すのでなく、その道を無くした。

- **この Mac では、ランナーが自分で起こしてまだ刈り取っていない子と、その子が leader の group にだけ signal を送る**。送るのは各 xcodebuild を見張る perl だけで、`waitpid` で刈り取る前なので番号は使い回されない。シェルは番号に送らない。Python には signal を送る口が無い（`OsPort` から `signal`・`signal_group` を消し、`os.kill`・`os.killpg` はソースのどこにも無い）
- **前の回の残骸は、この Mac では止めない**。何が残っているかを決まった語彙（`NTK-STALE:alive <数> process(es) (<数> xcodebuild, <数> tool, <数> group, <数> sample, <数> unknown)`、`NTK-STALE:refused <理由>`）で知らせ、場所は出さない。止めるのは利用者で、再起動でも消える。フォルダーは、その回のものが何も動いていないと示せたときだけ消し、示せなければ残す。残ったフォルダーがあれば、許可を得た回は組む前に止まる
- **同じ回の中では、前の xcodebuild を刈り取り、その group に何も残っていないことを確かめてから次を起こす**（`settle`）。起こした group はすべて印に残す
- **実行ファイルを読めない・一覧を読めないときは、送らず消さず残す**
- VM の中は今のまま（使い捨てなので、`pkill` などの片付けはそのまま）。xcodebuild の見張りは同じ perl を使う

`agent-rules/device-testing.md` の macOS の節に「この Mac では、ランナーは自分の子にしか signal を送らず、前の回の残骸は止めずに知らせる」を足した。
