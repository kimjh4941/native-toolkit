## 強み（両者）

- `ReturnGate` の待ち方は main を同期に待たせず、受け付けたすべての入口と受け手の登録が門を通る。静的には単独のデッドロックや再帰の積み上がりは無い（両方）
- 通知の転送は、iOS の router と同じ構造（`CompletionOnce` は lock を外してから呼ぶ、循環の防止は転送の間 lock を持たない、`nil` の設定の転送）（両方）
- `isActive` の近道を外したことで、`willFinishLaunching` での誤った分類が直り、形 1・2・3 とも `main()` の中で記録が始まる（両方）
- `PickerBox` の強い保持と、自動で閉じる処理の箱経由は効いている。delegate は weak で保持の循環は無い（両方）
- Unity 6000.4.2f1 の Mono では、`Main.cpp` の雛形・`PlayerMain` の公開・`PlayerApplication`・リンクと埋め込みの処理から見て、書き出しの経路を否定する要因は無い（Codex。実の書き出しの成功の確かめではない）

## 確かめ（直した後）

- 組み直し: Xcode 26.6、Swift の警告 0 件。C ABI の公開シンボルは arm64・x86_64 とも `_ntk_*` の 20 個だけ（足した 1 つ: `ntk_probe_redact_path`）。symlink 5 本ずつ、install name `@rpath/…/Versions/A/…`、rpath に `@loader_path/../../..`。本体はリンカーの ad-hoc、bundle としては署名なし、`ditto` の写しを ad-hoc で署名し直すと `codesign --verify --strict` が通る
- smoke: `HOME` を偽の container に向け、arm64・Rosetta の x86_64 のそれぞれで、普通と遅延のフック（300 ms）付きの計 4 回、54 件ずつすべて通った（FAIL 0）。別のスレッドからの呼び出しの時刻は記録だけ（フック付きで入口 301〜310 ms、完了はその後 0.1〜1.6 ms）。`dlopen` の兄弟の置き方も 2 つのアーキテクチャで通った（読み込み元は dyld の一覧で確かめた。describe はパスを伏せるので）
- `unity/Main.cpp` は 0〜3 の形でリンクでき、`unity/NtkProbeMac.cs` は Unity 6000.4.2f1 の Roslyn でコンパイルが通った（どちらも動かしていない）
- この Mac では画面・通知・クリップボードを使うものは動かしていない（区分 1 だけ）
