## この Mac にとっての意味

- この Mac で通知のテストを流している間に、ほかのアプリ（メールなど）の通知がサンプルの根を押す直前に来ると、その通知を押しうる（その通知のアプリが開く）
- 今の準備の「集中モードを入れ、通知を許すアプリをサンプルだけにする」（`agent-rules/device-testing.md`）が、この競合を防ぐ守りになる。ほかのアプリのバナーが出なければ、押す点が替わらない
- 次の段取りの案: VM で、サンプルだけを許す集中モード（またはおとりの通知の許可を切った状態）で同じ回を流し、おとりのバナーが出ず到達 0 であることを確かめ、その準備を前提の条件として記録する。テストの側では、サンプルのイベントを期待する経路（本文・`Open`・`Reply`。N21〜N24、NC1〜NC3）なら、押し違いでイベントが来ずに落ちうる（今回の NC1 も落ちた）。`Options` や許可の問い合わせの項目、N20（イベントが 0 のままを確かめる）では、押した先を後の確かめで示せない（ランナーのレビュー v7 の Codex C-2 で「必ず見える」を直した）

## 2. 押下の前後の照らしを足した後（2026-11-28 の 2 回目。値はまだ None）

### 直したこと（Support。Codex の確かめと、ハッシュの固定はこの後）

- `NotificationCenterUI.pressInCenter`: 通知センターへのクリック 5 か所（本文、`Options`、メニューの項目、許可の問い合わせの `Options` とその項目）をこの 1 つにまとめた。通知センターが見せているグループを、確かめの始め・押す直前・押した直後に読み（`groupLayout`。identifier と枠だけで、label は読まない）、確かめの始めと押す直前で違えば押さずに止め（`Notification Center changed between the check and …; nothing was pressed`）、押した直後に新しいグループが出ていれば「押下が別の通知に届いた疑い」で落とす（`… arrived while pressing …; the press may have reached another notification`）
- 窓の一覧（`CGWindowList`）では比べられなかった: VM で確かめると、通知センターはバナーをすべて 1 つの全画面の窓（番号・層・枠が変わらない）に描くので、バナーが来ても窓の一覧は変わらない。そのため通知センターの要素の木で比べる
- 要素に向けた操作（位置でなく要素を指す押下）: XCUITest の macOS の公開の API には無い（`click()` は要素の hit point に合成のイベントを送る。`typeKey` は入力の焦点に送る）。ランナーから `AXUIElementPerformAction` を使うと、UI テストのランナーにアクセシビリティの許可を新しく与える必要があるので、この Mac の設定の変更になり採らなかった
- 残る窓: 最後に読んでから XCTest が実際のイベントを合成するまでの間に、長さを保証できない競合が残る（数 ms とは言えない。Codex のレビュー C-1）。押下を受けた通知がその後に消えれば、押した直後の照らしでも気づけない（同 A-1）。この Mac では UI テストを流さないことにした（D-21 の見直し、2026-11-28）ので、この照らしは VM の合成のおとりでの検出の強化として残す
- 自己テスト `NotificationCenterPress`（クリックはこの口だけ、読む順、identifier と枠だけ）。変異を 4 つ足した（押す前の比べを外す、押した後の比べを外す、枠を比べない、素のクリックに戻す）

## 3. Codex の押下の直しのレビュー v1（scratchpad の `review/presscenter-codex-v1.md`）と扱い

- **A-1（致命的）**: 最後の観測の後に来た通知が押下を受けて消えると、押した直後の照らしでも気づけず、私物のアプリを開く道が残る。**この Mac では UI テストを流さない（D-21 の見直し）ので適用外**。VM の合成のおとりでの検出の限界として記録する: 押した直後の照らしは「新しいグループが残っている」ときだけ落とし、押下を受けて消えた通知は捉えない。その場合、サンプルのイベントを期待する経路ならイベントが来ずに落ちうるが、`Options` や許可の問い合わせの項目のように後の確かめが押した先を示さない押下もある（ランナーのレビュー v7 の Codex C-2）。D-21 の見直しによるこの Mac からの隔離と、VM の中の押し違いの検出は、別の保証として扱う
- **B-1（既知の限界。ランナーのレビュー v7 で直した）**: 自己テストと変異は、照らしの文字列と順を見るだけで、比べる関数に合成の入力を与えて、追加・置換・合流・重なりを区別できるかを確かめていない。identifier が空・重複のときに安全と推定しない形にもしていない。→ 比べる処理を純粋な関数 `CenterLayoutRule`（`Support/NotificationRules.swift`）に分け、`SupportRuleTests` の合成の入力で可否つきに確かめる形にした（作業の記録の 22 章）
- **C-1（直した）**: 「残るのは数 ms」を、長さを保証できない競合が残る、という言い方に直した（Support のコメント、`--dry-run` の文、この記録）
