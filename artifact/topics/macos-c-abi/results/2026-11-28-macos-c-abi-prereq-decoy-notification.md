# 前提の確かめ: おとりの通知（VM。途中。通っていない）

- 日付: 2026-11-28
- 項目: `MAC_RUN_PREREQUISITES["decoyNotificationRoot"]`（設計書 6c、7 章「根（動き）」、作業の記録 19 章）
- 場所: VM `ntk-macos-15-new`（macOS 15.8.3、Xcode 26.3）。リポジトリは `87df89ae` に 20.1 の直しを足した作業ツリー
- 結果: **通っていない。値は None のまま**。おとりの後着のバナーに、サンプルの根を狙った押下が 1 回届いた（`didReceive` 1）

## 道具（VM の写しにだけ置き、コミットしていない）

- おとりのアプリ 2 つ: `dev.ntkprobe.decoya`（表示名 `NtkDecoy`）と `dev.ntkprobe.decoyb`（表示名 `MacLibraryExample`）。サンプルと同じ題・本文（`Immediate Notification` / `Displayed now`）と category（`mac-sample-category`、`Open`・`Reply`、同じ placeholder）の通知を、引数の秒ごとに出し、届いた `didReceive`（action・文字）を書く。通知の許可は `com.apple.ncprefs` にサンプルと同じ値の項目を足した
- `scripts/test_mac.sh --where vm --feature Notification`（`--keep-vm-run`）を、おとりを出しながら流し、N20〜N24・NC1〜NC3 の結果のバンドルの手順の時刻と、おとりを出した時刻から、サンプルのバナーが来た時刻（Show の押下、NC は +10 秒）に対しておとりが前に来たか後に来たかを分けた

## 結果

| 回 | おとり | N20〜N24・NC1〜NC3 | おとりに届いたもの |
|---|---|---|---|
| 強い負荷（段取りに無い） | `NtkDecoy`、2 秒ごと | 8 件とも落ちた（N13 も）。どれもサンプルの根が見つからず（`found 0`、`no root`、`No matches found`）押す前に止まった | 0 |
| A6-1 | `NtkDecoy`、6 秒ごと | 6/8。前に来た形 8 件、後に来た形 1 件（NC3、+0.1 秒、通った）。落ちた N20・NC1 は根が見つからず押す前に止まった | 0 |
| A6-2 | `NtkDecoy`、6 秒ごと | 6/8。前に来た形 8 件、後に来た形 2 件（N20 は待ちの間に 6 通、通った。NC1 は +1.6 秒）。N23 は根が見つからず止まった。**NC1 は、根を見つけて押す前の確かめを通った後、押す 0.2 秒前に届いたおとりのバナーが同じ場所に出て、押下がおとりに届いた**（おとりの `didReceive` に既定の action が 1 回。サンプルは起きず `NTK-STEP:coldStart` で落ちた） | **1** |

- 前に来た形（16 件）では、おとりに届いたものは 0 で、落ちたもの（4 件）はどれも根が見つからず押す前に止まった
- 後に来た形のうち、押す直前（0.2 秒前）に別のアプリのバナーが来た場合、根の照らしと押す前の確かめ（窓の持ち主）を通った後に、押す点がそのバナーに替わり、押下が届いた。確かめと押下の間の競合で、テストの側の確かめだけでは閉じられない
- `MacLibraryExample` を表示名にしたおとり（`decoyb`）は、まだ流していない

## この Mac にとっての意味

- この Mac で通知のテストを流している間に、ほかのアプリ（メールなど）の通知がサンプルの根を押す直前に来ると、その通知を押しうる（その通知のアプリが開く）
- 今の準備の「集中モードを入れ、通知を許すアプリをサンプルだけにする」（`agent-rules/device-testing.md`）が、この競合を防ぐ守りになる。ほかのアプリのバナーが出なければ、押す点が替わらない
- 次の段取りの案: VM で、サンプルだけを許す集中モード（またはおとりの通知の許可を切った状態）で同じ回を流し、おとりのバナーが出ず到達 0 であることを確かめ、その準備を前提の条件として記録する。テストの側では、押した後に `didReceive` の相手（サンプルのイベント）を確かめているので、押し違いは落ちとして必ず見える（今回の NC1 も落ちた）
