## 第 2 回の指摘と反映方針

`指摘者` の略号: ①＝Claude ①、②＝Claude ②、C＝Codex。

### 高優先度

| # | 指摘 | 指摘者 | 反映方針 |
|---|---|---|---|
| S-1 | **通知の `release`**。(a) 配送中の件数で決めると、C++ がハンドラをコピーした後、呼ぶ前に close が入った場合に、`release` の後で古いハンドラが呼ばれる。(b) `manager_create` と `set_invoked_handler` が失敗したときに `release` を呼ぶかが決まっていない | ① ② C | (a) provider と同じ **`shared_ptr` の解放ガード**にする。C ABI のハンドルがガードへの参照を 1 つ持ち、`SetInvokedHandler` か `Close` が戻った後、C++ のロックの外で手放す。(b) **`release` を取る関数はすべて、`release != NULL` なら戻り値にかかわらずちょうど 1 回呼ぶ**。失敗したときは、呼び出しスレッドで関数が戻る前に呼ぶ。閉じたマネージャーへの `set_invoked_handler` は `NOT_INITIALIZED` を返し、その場で `release` を呼ぶ |
| S-2 | **生存フラグのミューテックスでの自己デッドロック**。コールバックの中のモーダルなループや自分の書き込みで、同じスレッドの provider、`release`、履歴の完了が入れ子で来る | ① ② | コールバックの間はロックを持たない。ロックの下でフラグを確かめて**呼び出し中の件数**を増やし、ロックを外して呼び、戻ったら減らす。`_free` はフラグを倒し、**自分以外のスレッドの呼び出し中の件数**が 0 になるまで待つ。コールバックの中からの `_free` は引き続き禁止し、Debug ではスレッド ID で assert する |
| S-3 | **provider の `release` の時期**。自分の書き込み（`copy_*`、`clear`）でも手放される。次の予約は成功ではなく `EmptyClipboard` に達した時点で前の分を手放す。close の後も残り、DLL のアンロード時（ローダーロックの中）に呼ばれる | ① ② C | 表を実装どおりにする。**close が成功したら、close が戻る前にオーナーのスレッドで呼ぶ。`_free` の時点でまだなら、`_free` の中で呼ぶ。`_free` が戻った後は呼ばない**。C ABI の解放ガードに「呼んだ」の印を持たせ、C++ に残るコピーが後で消えても何もしない。close の中で provider が呼ばれうること（`WM_RENDERALLFORMATS`）を書く |
| S-4 | **ドメインリロードの中で close を成功させる手段が無い**。処理中の履歴の要求があると close は `CANCELED` を返す。取り消しの配送は自分の隠しウィンドウ宛てなので、メッセージを回さないと終わらない。リロードの最中に Editor のメッセージループを回すのは危険 | ② | **利用者の判断が要る**（下の「利用者に確かめる点」） |
| S-5 | **履歴のハンドラの差し替え**。C++ はオーナーのスレッドか確かめる前にハンドラを差し替える。さらに、解除（`StopWatch`）に失敗すると古い登録が残る | ① C | C++ の順序を直す（オーナーのスレッドを先に確かめる）。C++ の不具合なので T-17 で直す（E-20）。7.5.1 は「差し替えか解除が**成功した**後」に直し、失敗したときは古い `user_data` がまだ使われると書く |
| S-6 | **付録 A の 3 つのヘッダーに include ガードと `extern "C"` が無い**。C++ から使うとリンク名が合わない | ① C | 各ヘッダーにガードと `extern "C"` を書く。構造体は `#pragma pack(push, 8)` / `pop` で囲む（下の S-7） |
