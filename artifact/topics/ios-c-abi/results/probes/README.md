# probes

確かめるのに使った使い捨てのコード。ビルドには入れない（記録として置く）。

| フォルダ | 段階 | 中身 | 動かし方 |
|---|---|---|---|
| `xcode-facts/` | UI テストの設計書（v3 のレビュー） | `FactProbeTests.swift`（基底の `final setUpWithError`、`self.name`、`XCTSkip` の後の tearDown、JSON のリソース） | テストのターゲットに写し、`FactProbe.json` を同じ場所に置いて `-only-testing` で流す。結果は 0a の結果の 8 章 |
| `stage0a/` | 0a | `Stage0aProbeTests.swift`（XCUITest。Dialog、通知の権限、通知のバナー・通知センター・アクション・テキスト入力・コールドスタート・予約、Share のシート、貼り付けの許可と `UIPasteControl`）、`noscene/`（scene の無い UIKit のアプリ。`IosLibrary` の key window の探し方を確かめる）、`run.sh`（`-only-testing` で選んで流す）、`stability.sh`（3 回の安定の確認）、`run-device.sh`（実機の iPhone XS で流す。`-destination` に使うハードウェアの UDID（`devicectl device info details` で分かる。devicectl の識別子とは別の値）を環境変数 `STAGE0A_DEVICE_UDID` で渡す。端末を特定できる値なので、リポジトリには書かない） | `Stage0aProbeTests.swift` を `ios/IosLibraryExample/IosLibraryExampleUITests/` に写す（ファイルシステムと同期するグループなので、プロジェクトの編集は要らない）。作業用のフォルダを `STAGE0A_WORK` に指定し、`xcodebuild build-for-testing -workspace ios/IosWorkspace.xcworkspace -scheme IosLibraryExample -destination 'platform=iOS Simulator,id=<UDID>' -derivedDataPath $STAGE0A_WORK/dd` の後に `run.sh <UDID> <ラベル> <クラス[/テスト]>...`。権限のテストは、毎回 `xcrun simctl uninstall <UDID> com.jonghyunkim.ios.nativetoolkit.example` の後に 1 件ずつ流す。`run.sh` はシミュレーター 2 台の UDID 以外を拒む。`noscene/` は `swiftc` で組んで ad-hoc 署名し、`simctl install` / `simctl launch --console-pty <UDID> com.jonghyunkim.stage0a.noscene alert|share` で動かす（組み方: `xcrun swiftc -sdk $(xcrun --sdk iphonesimulator --show-sdk-path) -target arm64-apple-ios18.0-simulator -swift-version 5 -F <IosLibrary.framework のあるフォルダ> -framework IosLibrary -Xlinker -rpath -Xlinker @executable_path/Frameworks -o NoScene.app/NoScene main.swift`、`Info.plist` と `Frameworks/IosLibrary.framework` を入れて `codesign -s - --force`）。`simctl launch --stdout=` はファイルに書かれなかったので `--console-pty` を使う。実機では、`build-for-testing` を `-destination 'platform=iOS,id=<実機のハードウェアの UDID>' -allowProvisioningUpdates -derivedDataPath $STAGE0A_WORK/dd-device` で組んでから `run-device.sh <ラベル> <クラス[/テスト]>...`。実機では階層のダンプを出さず、Share のシートの共有先の名前はログに書かない（私物の端末のため） |
| `stage0c/` | 0c | `Stage0cProbeTests.swift`（前半: 監視の経路、I1 の集め方、action sheet の形、権限と貼り付けのダイアログのラベル）、`Stage0c2ProbeTests.swift`（後半: 広げた通知の要素、同じ id の更新の件数、添付の 2 回、前面のバナーのタップ、背景で起動したプロセスの残り方、設定の App の前面、カレンダーの発火の時間、アイコンのバッジ、位置の予約の登録、category の反映、Share のプレビューの題・複数の Copy・Save to Files、貼り付けの許可のダイアログが出る条件、画像だけの貼り付け、`activate` の直後のフレーム）。どちらも `SampleUITestCase` を継承し、`Support/` の補助を使う | テストのターゲットに写し、`Support/DeviceRequirements.json` にクラスのテストのキーを足して（区分は `systemui`・`sharesheet`・`clipboard`・`files`）、シミュレーターだけで `-only-testing` で流す。終わったらファイルとキーを消す。結果は 0c の作業の記録と結果のファイル |
