## サーキットブレーカー

私物の端末を守る仕組みへの区分 A は、v1 から v4 まで 4 回続いた。v1〜v3 の直しは、どれも「見つかった抜け道を塞ぐ」形だったので、XCTest と Swift の別の入口（`super` を呼ばない setUp、識別子の直書き、`XCTFail` の後の継続、基底クラスの列挙、別の teardown、`invokeTest`、`#if`、継承）が次々に見つかった。review-document の「同じ種類の指摘が 3 回続いたら、それを生む仕組みを直す」に従い、守りの考え方を次のように変える。

### 仕組みの直し（2）

1. **閉じた形の規則（許す形を決め、ほかを禁じる）**。UI テストのターゲットのソースの検査を、禁じる API を並べる形から、許す形だけを決める形に変える
   - 基底のファイル（`Support/` の決まった 1 ファイル）の外のクラスは、どれも `final class <名前>: <基底>` だけ。基底の外のクラスを継承するクラス、`final` でないクラスは禁じる（今の `ClipboardUITests` も `final class ClipboardUITests: <基底>` にする。ハッシュで固定するので、外すと止まる）
   - 基底のファイルの外では、`override` は決まった口（`setUpAfterGate()`、`tearDownAfterGate()`）だけ。`class func`、`static func` の上書き、`#if`、`import` は `XCTest` と `Foundation` のほかを禁じる（Swift Testing の `import Testing` も禁じる）
   - `XCUIApplication`、`XCUIDevice`、`UIPasteboard`、`addUIInterruptionMonitor` の型の名前は、`Support/` の決まったファイルの中だけ
   - 基底は `invokeTest` を上書きしない（子が上書きできないことは上の規則で決まる）。基底の setUp / tearDown の入口（同期・async）は `final` にし、決まった口へ渡す
2. **実機のビルドのテストの一覧をバイナリから読む**。実機のビルドの `.xctest` のテストのクラスとメソッドを、端末で起動せずに読み（`nm` などで Objective-C のメタデータの `test` のメソッドを挙げる）、シミュレーターの列挙と一致することを照らす。`#if` で実機にだけあるテストは、ここと 1 の両方で止まる
3. **実機で流すときの最終の守りは、利用者の許可**。実機で流す前に毎回、ランナーが流すテストの名前と区分の一覧を出し、利用者が見て許可してから流す（README の D-21、利用者の指示と同じ）。許可した一覧と結果の集合がちょうど同じかをランナーが照らす
4. **区分の扱い**: 守りの本体は、一段目（ランナーが選ぶこと）、宣言の正しさの照合（クラスの下限、固定、閉じた形の規則、実機のバイナリの一覧）、利用者の許可の 3 つとする。テストの中の確かめ（二段目）は宣言の誤りを実行時に見つける補助で、**二段目だけの穴は、以後は区分 B として扱う**

## 指摘と対応

### 区分 A

| ID | 出典 | 指摘 | 対応 |
|---|---|---|---|
| A-18 | Codex | `tearDownWithError` のほかに `tearDown()`、`tearDown() async throws`、`class func tearDown()` の入口がある | 仕組みの直し（2）の 1（基底の外での `override` と `class func` を禁じる。基底の入口は `final`） |
| A-19 | Codex | `invokeTest` を上書きして `super` を呼ばないと、全件が空で成功しうる | 基底は `invokeTest` を上書きしない。子は 1 の規則で上書きできない |
| A-20 | Codex | `#if !targetEnvironment(simulator)` の中のテストは、シミュレーターの列挙に出ず、実機で黙って流れない | 仕組みの直し（2）の 1（`#if` を禁じる）と 2（実機のバイナリの一覧と照らす） |
| A-21 | Codex | `.xcresult` を消す trap の登録が遅く、HUP と、シグナルの後の終了を扱っていない | 一時フォルダーを作った直後、最初の実機の xcodebuild の前に trap を登録する。EXIT で消し、INT / TERM / HUP では対応する終了コードで `exit` して EXIT の trap を走らせる |
| A-1v4 | Claude | `class Foo: ClipboardUITests {}` を足すと、22 件を継承して流し、下限・固定・ソースの検査を通る | 仕組みの直し（2）の 1（`final class` だけ、基底の外のクラスを継承しない）。ランナーでも、固定した 22 のメソッド名が別のクラスの下に出たら止める。7 章に変異を足す |
| A-2v4 | Claude | 監視が、`[]` や `clipboard` だけのテストでも、否定のボタン（キャンセル、今はしない）を持つどのアラートでも押す。テストと関係の無い私物のシステムのアラート（キャリア設定のアップデート、Apple ID の確かめなど）に答えてしまう | 実機では、押してよいのは「そのテストが `systemui`（ペーストの拒否は `clipboard`）を宣言し、かつアラートのラベルにサンプルの表示名（`IosLibraryExample`）が入る」ときだけ。ラベルは読むだけでログに書かない。それ以外は押さずに terminate して印を立てる |
| A-3v4 | Claude | CB1 は監視を外して `Allow Paste` を押し、CB3・CB4 の `UIPasteControl` はダイアログを出さずに読むので、ランナーが書いてから押すまでの間に Mac でコピーされると、利用者の Mac の内容を読む | 実機で `clipboard` を許すときは、Handoff を切ることを流す条件にする（尋ねるのではなく前提にする）。ランナーが書いた直後と押す直前で `UIPasteboard.general.changeCount` が変わっていないことを確かめ、変わっていたら押さずに失敗にする。ほかの端末の内容で `changeCount` が上がるかは 8.1 に足す |
| A-4v4 | Claude | `NTK-` 以外の skip は理由を問わず `skipped` として基準に入り、いつも skip するテストが確かめないまま成功と報告される | 意図した skip の一覧（テストのキーと理由の前方一致。今は U10b と U21）をランナーに持たせ、それ以外の skip は失敗にする。純粋な関数にして `scripts/tests/` に置き、7 章に「別のテストに `XCTSkip` を足す」変異を足す |
