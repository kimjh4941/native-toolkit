## 強み（2 者に共通）

- 期待値（S-P17・8.5.6・5.12.3）はコードと合う。2.0.0 の `getScheduled`・`getDelivered` は印で絞らない。前の delegate が無いとき、印の無い応答はライブラリの `responses` に届き、サンプルの最後のイベントの行に出る。サンプルの起動で通知や category を消す処理は無い
- 1.x と 2.0.0 で ID、category の識別子、アクションの題、バナーの題と本文が一致している
- 組を分けて、予約の ID が 1 つしかないことを避けている。信頼する部分とシミュレーターだけの扱いは方針に沿う

## 改善点と対応（v2 で直した）

| ID | 重さ | 問題 | v2 での対応 |
|---|---|---|---|
| C-1 | A | 差し替えた `.xctestrun` の `UITargetAppEnvironmentVariables` の `DYLD_FRAMEWORK_PATH` などが今の組み立てを指し、1.x のアプリが 2.0.0 の `IosLibrary` を読みうる。前提の確かめの「前面に来なかった」の原因の説明も誤り | 測って確かめた（そのとおりだった）。探し先も 1.x の置き場に替える形にし（U-2）、8 章を直した |
| K-1 | A | 差し替えが効かず 2.0.0 → 2.0.0 になっても全部通る | 毎回、版を確かめる（U-4）。前半で 2.0.0 の識別子が 0 個であることを見る。変異 UM3 |
